# go-burp — Go parser for Burp project files

Go implementation of the Burp Suite `.burp` project format, built with
[Kaitai Struct](https://kaitai.io). Output is validated byte-for-byte against
the `prub` Python reference parser (see `../prub`) on both controlled samples
(`2026-09-23.burp`, `2026-09-23-empty.burp`), covering metadata, Proxy history
(28 + 17 items), Repeater tabs/pairs (including a zero-length request record),
and the Target site map (337 nodes, 281 with messages).

## Layout

| File              | Purpose                                                                 |
| ----------------- | ----------------------------------------------------------------------- |
| `../burp.ksy`     | Kaitai Struct definition of the format's structural layer               |
| `burp_project.go` | Generated by `ksc -t go` — do not edit, regenerate instead              |
| `nav.go`          | Graph navigation: forwarding resolution, collections, strings, roots    |
| `cmd/burpdump`    | CLI: dumps metadata / proxy / repeater / target / raw records as JSON   |

## Build and regenerate

```sh
# regenerate the structural layer after editing burp.ksy (ksc 0.11)
ksc -t go --go-package burpfmt --outdir go-burp burp.ksy
mv go-burp/burpfmt/burp_project.go go-burp/ && rmdir go-burp/burpfmt

cd go-burp
go build -o burpdump ./cmd/burpdump
./burpdump all ../2026-09-23.burp          # or metadata|proxy|repeater|target
./burpdump record ../2026-09-23.burp 434302 # hex-dump one raw byte record
```

## Design notes

The format has two properties that shape the definition:

- **Absolute addresses.** Persisted references are signed 64-bit file offsets;
  0 means "absent". The generated code seeks a shared stream, so one
  `kaitai.Stream` over the whole file serves every read.
- **Self-describing compact objects.** Each object starts with a descriptor
  table (`field_id -> relative_offset`) whose entries are ordered by data
  layout, not by field id. Pure Kaitai cannot "search" a table, so `burp.ksy`
  encodes the lookup declaratively: the `find_*` types `repeat: until` over
  descriptors until `entry.last.field_id == target` (or the table end, tracked
  via `_io.pos >= table_end`), then read the typed value at
  `base + relative_offset`. Absent fields stay `nil` thanks to the guarded
  value instance.

`nav.go` adds what belongs in code rather than in the spec: forwarding-record
resolution (cycle-safe, depth 16), collection walking (chunked `Zwtw` and
direct `Zg_i`), UTF-16BE decoding, UUID formatting, and the typed roots.

## Kaitai 0.11 gotchas hit while building this

Recorded here because they cost real time; they differ from 0.9/0.10 docs:

- Type arguments are **positional call syntax** in the `type` field:
  `type: "find_i32(1, base, obj.table_end)"` (quoted — `:` inside breaks YAML).
- `repeat: expr` / `repeat: until` must accompany `repeat-expr` / `repeat-until`.
- `pos` is only valid on parse **instances**, never on seq entries.
- `args:` maps no longer exist anywhere.
- `params` entries should carry explicit `type:`; untyped params are treated
  as bytes and break arithmetic.
- The Go backend does not widen operands in binary expressions: `s8 + u1`
  fails to compile. Cast explicitly, e.g. `descriptor_count.as<s8> * 3`, and
  cast the *whole* value-instance expression (`((...).as<s8>)`) because
  arithmetic re-widens to `int` afterwards.
- Inside `repeat-until`, the seq id refers to the array; use `entry.last`
  for the element just read (it is the current element at condition time).
- Root-level seq entries cannot use `pos`/`args`; park such reads in an
  intermediate type (`roots`) as parse instances.

## Validation

```sh
# ground truth
python3 /tmp/opencode/burp/dump.py 2026-09-23-empty.burp > /tmp/prub-empty.json
python3 /tmp/opencode/burp/dump.py 2026-09-23.burp       > /tmp/prub-full.json

# parse with Go and compare (json-normalized)
go-burp/burpdump all 2026-09-23-empty.burp > /tmp/go-empty.json
go-burp/burpdump all 2026-09-23.burp       > /tmp/go-full.json
python3 -c "import json; a=json.load(open('/tmp/go-empty.json')); b=json.load(open('/tmp/prub-empty.json')); print(a==b)"
python3 -c "import json; a=json.load(open('/tmp/go-full.json'));  b=json.load(open('/tmp/prub-full.json'));  print(a==b)"
```

Both comparisons print `True`. Scope and field semantics follow
`../prub/ai-docs/format-specification.md`; unknown fields and object types
remain structurally inspectable (`CompactObject` exposes the whole descriptor
table) but carry no product-level meaning yet.
